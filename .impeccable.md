# Impeccable Design Context — Infodays CTF

## Design Context

### Users
University students and club members participating in a CTF security competition. Tech-savvy but not necessarily expert security researchers. They are motivated, competitive, and comfortable with technical interfaces. They use the platform under time pressure during the event — scanning challenge statuses, launching instances, submitting flags. Speed and clarity matter more than hand-holding.

### Brand Personality
**Competitive. Technical. Sharp.**

The platform should feel like a serious competition arena — not a classroom tool, not a corporate SaaS product. It should give participants the feeling that they are in the right place to compete. Tense, focused, precise.

Emotional goals: confidence when a challenge instance starts, urgency when the clock is ticking, satisfaction when a flag submits. No whimsy, no filler.

### Aesthetic Direction
**Primary reference: HackTheBox** — dark moody backgrounds, minimal chrome, clean typography, accent colors used sparingly and with purpose, terminal/data aesthetic for technical elements.

**Dark mode is the canonical experience.** Light mode is a clean inversion for those who prefer it — not an afterthought, but not the primary target.

**Anti-reference: generic Bootstrap.** No default rounded blue buttons, no friendly pastel cards, no corporate whitespace-heavy layouts. The platform should not look like it was scaffolded and left unstyled.

**Visual tone:** near-black navy backgrounds, tight spacing, sharp or subtly-rounded corners (2–4px max), monospace for all data outputs (flags, ports, IPs, status codes), minimal use of color — the blue primary and orange-red accent land with impact precisely because everything else is dark and restrained.

### Typography

**Body & UI:** [Inter](https://fonts.google.com/specimen/Inter) — modern geometric sans-serif, excellent legibility at small sizes, used by linear.app, Vercel, and the broader technical SaaS space. Clean without being corporate.

**Code, flags, ports, IPs, terminal output:** [JetBrains Mono](https://fonts.google.com/specimen/JetBrains+Mono) — purpose-built for code readability, distinctive character shapes reduce errors when reading flag strings.

**Scale (Bootstrap 5 overrides):**
- Base: 14px / 1.5 line-height
- Labels / badges: 11–12px, letter-spacing: 0.04em, uppercase for status labels
- Headings: Inter 600–700 weight, tight tracking

### Design Principles

1. **Terminal precision** — Data is always monospace (flags, ports, IPs, hashes). Labels are tight, uppercase, letter-spaced. No decorative elements that don't carry information.

2. **Dark-first, light-aware** — Every component is designed for dark mode first using CSS custom properties mapped to the token set. Light mode is a mechanical inversion via `data-bs-theme`, not a separate design.

3. **Competitive urgency** — Status indicators, instance states, and timers are the most important elements on screen. They must be immediately legible: clear color coding (blue = active, red = error/destructive, muted = inactive), large enough to scan at a glance.

4. **Restraint amplifies impact** — The blue primary (`#397BE9`) and chevron orange (`#E84B2A`) are used sparingly. Backgrounds carry the weight. A single blue button in a dark card has more presence than a page full of color.

5. **Student-accessible sharpness** — Sharp doesn't mean cryptic. Actions are clearly labeled, states are named not just colored, and error messages say what happened. The aesthetic is serious, not hostile.

### Technical Constraints
- **Bootstrap 5** CSS variable system — all tokens map to `--bs-*` overrides
- **Vanilla JS** — no build step, no framework; all component logic in `ctfd-plugin/assets/plugin.js`
- **Inline styles must be replaced** with CSS custom properties to respond to `data-bs-theme` switching
- **CTFd plugin Blueprint** serves static assets from `ctfd-plugin/assets/` — fonts loaded via Google Fonts CDN in `__init__.py`
